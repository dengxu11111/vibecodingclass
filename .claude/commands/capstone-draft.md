# /capstone-draft — 三角色协作起草综述

按 capstone 的简化版三角色流程，把 `data/processed/` 的 CSV 和 `outputs/` 的图变成一篇 600-1000 字综述。

## 前置检查

- `capstone-科研数据分析/data/processed/趋势汇总.csv` 必须存在（如无，告诉用户先跑 `/capstone-run`）
- `capstone-科研数据分析/outputs/` 下三张 PNG 必须存在

## 角色 1：资料员

读 `data/processed/趋势汇总.csv` 和 `data/processed/era5_annual.csv`。
**只搬运 csv 数字，不允许补完任何字段**。

输出一张 Markdown 表格保存到 `capstone-科研数据分析/outputs/资料员_主题表.md`：

| 城市 | 窗口 | n | 30 年均温 (°C) | OLS slope (°C/年) | 95% CI | R² | 趋势方向 |

规则：
- 「趋势方向」填 `↑ 升温`（CI 全 > 0）/`↓ 降温`（CI 全 < 0）/`— CI 含 0`
- **不许**写"显著"二字
- 按 slope 从大到小排序
- 表后写 3 条「不能下结论的限制」：单像元、自相关未校正、7 城样本不代表全国

## 角色 2：起草员

读 `outputs/资料员_主题表.md` + outputs/ 下三张 PNG 的文件名（不需要识图，按名字推用途）。

写一篇 600-1000 字综述，回答：「1995-2024 年中国 7 座代表性城市的年均 2m 气温有没有变？哪些城市变得快、哪些慢？」

结构：
1. 数据与方法（80-120 字）：ERA5 + Open-Meteo + OLS + Student-t CI
2. 主要发现（200-300 字）：按 slope 从大到小列前 3 城，每城带数字 + CI + 趋势方向
3. 区域对比（150-200 字）：用资料员表里给出的归类，**不许自创**"沿海"、"内陆"
4. 局限（100-150 字）：自相关、单像元、城市选择

**禁用词**：显著、大幅、明显、确凿、毋庸置疑。改成"CI 不含 0"、"幅度较大"、"方向一致"。
**禁止**引入 ENSO、季风指数、城市热岛等无 csv 支撑的物理解释。

保存到 `capstone-科研数据分析/outputs/起草员_v1.md`。

## 角色 3：审稿员（合并 reviewer + critic + polish）

读起草员 v1 + 资料员表 + `趋势汇总.csv`。同时干三件事：

1. **挑错**：列出至少 3 个问题
   - 数字与 csv 不一致
   - 没数据支撑的程度词（包括"显著"）
   - 物理解释超出 30 年单点像元能支撑的范围
   - 自造的地理标签

2. **打分**（每项通过 / 不通过 + 一句证据）：
   - 每个数字都能回链 csv？
   - 没有禁用词？
   - 地理分类来自资料员表？
   - 字数 600-1000？
   - 4 个章节都齐全？

3. **重写 v2**：接受所有挑错，按建议改，**不动事实和引用**，每句 ≤ 40 字。末尾用一段「修改记录」列本轮改了什么。

输出**一份**文件 `capstone-科研数据分析/outputs/草稿_v2.md`，分两部分：
- 上半部分：审稿摘要（挑错 + 打分表）
- 下半部分：重写后的 v2 正文

## 角色 4：研究者（用户）

提示用户下一步：
- 跑 `/capstone-validate` 把 v2 里每个数字回链 csv
- 通过后把 `草稿_v2.md` 改成 `最终稿.md`，补一段「AI 使用声明」

## 用哪个模型

按你的条件选：
- 有 Claude Pro / API：起草员 + 审稿员都用 Sonnet 4.6
- 备用（无 Claude Code）：OpenClaw + DeepSeek-V3 三个角色都用，审稿员可换 DeepSeek-R1 加强批判
- 完全离网：跳过本命令，看 `example/capstone_5y_cds/` 里的 CDS 参考 CSV（Open-Meteo 30 年路径**没有**预装 example，要靠用户自己跑出来）

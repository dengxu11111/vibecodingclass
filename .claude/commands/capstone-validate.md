# /capstone-validate — 核验草稿数字

跑 `capstone-科研数据分析/05_核验.py`，确保草稿里每个数字都能在 CSV 里找到。

## 流程

1. **决定核验哪个文件**：
   - 如果 `capstone-科研数据分析/outputs/最终稿.md` 存在 → 核验它
   - 否则核验 `outputs/草稿_v2.md`
   - 都没有 → 提示学员先跑 `/capstone-draft`

2. **跑脚本**：
   ```
   python capstone-科研数据分析/05_核验.py
   ```
   （脚本会自动找最新草稿）

3. **读 `outputs/核验报告.md`**，按下面方法处理：

   - **untraced = 0** → ✅ 直接告诉学员"全部数字都能回链 CSV，可以定稿"

   - **untraced > 0** → 把 untraced 表格里的每条按下面 3 类分流：
     - **真编的数字**（csv 里完全找不到、context 是结论数字）
       - 建议学员删除或改写那一段。**这是最严重的**。
     - **精度问题**（csv 里有但精度不同，比如 csv 是 12.7 草稿写 12.70）
       - 建议学员要么改成 csv 同精度，要么用 `python 05_核验.py --tol 0.05` 放宽容差
     - **方法学引用**（"95% CI"、"2m 气温"、"1.96σ"、"R²=0.93" 这类）
       - 这些是教学描述，**不**算编数据
       - 建议学员在草稿里说清楚是引用方法/公式，必要时加白名单（见脚本顶部 `NOISE_PATTERNS`）

4. **报告格式**（用中文，给学员一个可执行的下一步）：
   ```
   核验结果：traced X / untraced Y

   ✓ 已通过：[简单一句]
   ✗ 待处理：[按 3 类分别列出条数和示例]

   下一步：[具体一条]
   ```

5. **如果脚本报错**（`FileNotFoundError` 等）：
   - 把错误用 `/explain-error` 的思路压缩成一句中文
   - 告诉学员先检查 `data/processed/*.csv` 和 `outputs/草稿_v2.md` 是否都存在

**不要**自己改草稿——只跑、只解释。修改草稿是研究者的工作。
**不要**自动放宽 `--tol` 跑第二遍——除非学员明确说"放宽"。

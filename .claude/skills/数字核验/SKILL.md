# 数字核验

## 何时使用

当用户：
- 让 AI 起草、润色一篇带数字结论的稿件
- 让 AI 从 CSV 总结趋势 / 排行 / 区间
- 准备把 AI 生成的草稿提交给导师 / 同行 / 期刊

每个数字结论都必须能在某行 CSV 找到——这是 AI 辅助科研的最低底线。

## 输入

- 草稿文件路径（Markdown / 纯文本）
- 数据 CSV 所在目录（默认 `data/processed/`）
- 容差（浮点默认 ±0.01，整数默认严格匹配）

## 工作流程

1. **判断是不是 capstone 项目**：如果是，直接 `python capstone-科研数据分析/05_核验.py <草稿路径>`，不要自己实现。
2. **不是 capstone**：按下面方法手动核验：
   - 列出 CSV 所有 cell 的数字（去重）
   - 用正则从草稿里抠数字
   - 跳过年份、章节编号、字数、日期片段、`n=X` 等方法学引用
   - 对每个抠出来的数字，看能不能在 CSV 数字池里找到容差内匹配
3. **报告**：按三类组织
   - `traced`（找到了）—— 一笔带过
   - `untraced 但是方法学引用`（"95% CI"、"R²"、"1.96σ" 等）—— 提示加白名单
   - `untraced 且是结论数字`（这是真问题）—— **逐条**报告行号 + 上下文，强烈建议删改

## 默认规则

- **永远不要**帮用户改稿，只报告。修改是研究者的事。
- 找不到数字池就停下，不要瞎跑。
- 浮点精度差异（13.4 vs 13.39）不算"编造"，按"精度问题"分类报告，建议用同精度或放宽 `--tol`。

## 输出格式

- traced 数 / untraced 数 / 总数
- untraced 表（行号、数字、上下文、建议分类）
- 一句话总结（可以定稿 / 需要修改 / 需要重写）

## 验收

- 报告里每个 untraced 都能给出明确的下一步动作。
- 报告不超过一页 Markdown（除非 untraced 真的特别多）。
- 退出码：traced 100% → 0；untraced > 0 → 非 0（便于 pre-commit / CI 接管）。

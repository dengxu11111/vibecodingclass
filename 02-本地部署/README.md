# 第 02 章 · 大模型本地部署与私有科研环境搭建

> 对应 PPT 第 17–28 页

## WHAT —— 学什么

- **核心对象**：Ollama、Open WebUI、Docker、Agent
- **真实场景**：实验室数据不能上云、需要 24/7 跑；或者想把 AI 接进只在内网的资料库
- **学习结果**：在自己电脑上跑起一个本地大模型 + 网页交互界面 + 一个有知识库的 Agent

## WHY —— 为什么学

- **痛点**：上云方案有数据合规风险、有 API 限速、关掉就没了；本地部署一次到位，资料留在本机
- **边界**：本地模型能力**永远不会**超过同等成本的云端模型；本章解决的是"可用、隐私、自主"而非"最强"

## HOW —— 怎么做（4 步）

1. 安装 Ollama 并验证小模型能跑（先 4B / 7B，跑通再升级）
2. 用 Docker 部署 Open WebUI 并连上 `localhost:11434`
3. 上传资料建立本地知识库（PDF / Markdown 都行）
4. 再用小模型完成一次"问知识库 → 出答案"的端到端验收

## 怎么用

```powershell
# 1. 装 Ollama 并拉模型
ollama pull qwen3.5:4b

# 2. 起 Open WebUI（需要先装 Docker Desktop）
cd 02-本地部署
docker compose up -d

# 3. 浏览器打开 http://localhost:3000，注册管理员账号、选模型开聊

# 4. 用脚本试一下 API 直连
python 测试本地模型.py
```

## 第一次跑通后做什么

跑通 `ollama run qwen3.5:4b "你好"` 只能证明模型能加载。要知道**它能干哪些活、不能干哪些活**，
打开 [示例任务/本地模型试金石.md](./示例任务/本地模型试金石.md) 跑 3 个 5 分钟评估任务（中文摘要改写 / 代码补全 / 拒绝编造）。
做完你会清楚：本地模型在你机器上的实际能力线在哪。

# 项目安全操作清单

> Agent 越强，误删风险越大。下面这张表区分"可放权 / 要 review / 要拦"。
> 在 Claude Code / OpenClaw / Codex 设置里都能配相应权限。

## 可放权的动作（Allow / 自动通过）

- 读文件、读目录、`ls` / `tree`
- 跑只读的 `git status` / `git diff` / `git log`
- 跑测试：`pytest`、`npm test`
- 跑只读的查询命令：`grep`、`find`
- 在沙盒 `data/`、`outputs/` 目录里写新文件

## 要 review 的动作（Ask / 手工确认）

- 修改业务源代码文件
- 新建文件 / 删除文件
- 写入数据库、调写 API
- 安装 / 升级依赖（`pip install`、`npm install`、`brew install`）
- 修改配置文件（`.env`、`docker-compose.yml`、CI 配置）
- `git commit`（哪怕 message 自动生成也要看一眼）

## 要拦截的动作（Deny / 永远不允许）

- `rm -rf` 顶层目录、`del /s` 大范围
- `git push --force` 到 main / master
- `git reset --hard` 已发布的 commit
- `drop table`、`truncate table`
- 把 API Key、密码写进版本控制
- 跳过 git hooks（`--no-verify`）
- 公开发布到 Slack / 邮件 / PR / Issue

## 怎么配（Claude Code 示例）

`~/.claude/settings.json`：

```json
{
  "permissions": {
    "allow": [
      "Bash(git status)",
      "Bash(git diff:*)",
      "Bash(pytest:*)",
      "Read(*)"
    ],
    "deny": [
      "Bash(rm -rf /*)",
      "Bash(git push --force*)"
    ]
  }
}
```

## 怎么配（OpenClaw）

在 OpenClaw 设置 → 权限管理里，把"文件写入"、"shell 执行"切到"每次询问"。

## 范围 / 权限 / 复用三原则

参考 PPT 第 13 / 27 / 55 页的反复出现的 HOW 公式：

| 维度 | 做法 |
| --- | --- |
| **范围** | 一开始只让 Agent 改一个小文件 / 一个子任务，跑通再扩 |
| **权限** | 只开必要路径和工具，其他默认拒绝 |
| **复用** | 验过的步骤封装成 Skill / 脚本，下次直接调，不要让 Agent 临场重新发明 |

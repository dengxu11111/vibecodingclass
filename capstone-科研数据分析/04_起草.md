# 04 · 起草（多模型协作 · 三角色简化版）

> 不写脚本，在 Claude Code / OpenClaw 对话里跑。三角色：资料员 → 起草员 → 审稿员。研究者（你）最后跑 `05_核验.py` 定稿。
> 五角色完整版（加批判员 + 润色员）见 [09-论文自动化/多模型角色分工.md](../09-论文自动化/多模型角色分工.md)。

## 强约束：用 MCP 取数，不让 LLM 自己读 csv

每个角色 prompt 都**必须**先用第 07 章配的 [vibecoding-capstone MCP](../07-MCP扩展/最小MCP-server.py) 拿数据，**不要** `read_file` 让 LLM 边读边写。理由：

1. 回链可审计：`load_trend_summary()` 返回结构化 dict，逐字段对照 csv
2. 核验自动化：`verify_number("0.0382")` 立即回 grep csv
3. 跨模型一致：DeepSeek / Sonnet / GLM 拿到的输入完全一致

**前置**：把 `07-MCP扩展/mcp配置样例.json` 的 `vibecoding-capstone` 合并到 `~/.claude.json`，重启 Claude Code。

## 输入

跑完前 3 步之后：

```
capstone-科研数据分析/
├── data/processed/{era5_monthly, era5_annual, 趋势汇总}.csv
└── outputs/{年均气温_折线, 趋势_条形图, 月气候态_热图}.png
```

Open-Meteo 路径跑不通 → 切 CDS 路径（`01_下载_cds.py` + `02_分析_cds.py`），或看 `../example/capstone_5y_cds/` 的 CDS 参考 CSV。

## 1. 资料员（DeepSeek-V3 / GLM-4.5）

```
你是【资料员】。

先调 vibecoding-capstone MCP 的 load_trend_summary() 拿 7 城趋势 dict（不要 read_file 读 csv）。

输出 Markdown 表格：
| 城市 | 窗口 | n | 30 年均温 (°C) | OLS slope (°C/年) | 95% CI | R² | 趋势方向 |

规则：
- 数字只能照搬 csv
- 趋势方向：↑ 升温（CI 全 > 0）/ ↓ 降温（CI 全 < 0）/ — CI 含 0
- **不许**写"显著"——CI 不跨 0 ≠ 物理显著
- 按 slope 降序
- 末尾 3 条「不能下结论」的限制：
  1. 单像元 OLS 残差自相关未校正
  2. 7 城样本不代表全国
  3. 0.25° 分辨率粗，城市热岛 / 站点选址未控制

保存到 outputs/资料员_主题表.md
```

## 2. 起草员（Claude Sonnet 4.6 / GLM-4.5）

```
你是【起草员】。

读 outputs/资料员_主题表.md 和 outputs/ 下三张 PNG 文件名。
写作中**每个数字**先调 verify_number("<num>") 确认 csv 有；找不到的不许写。

写 600-1000 字小综述，回答：
「1995-2024 年中国 7 城年均 2m 气温变了多少？哪些城市变得快、哪些慢？」

结构：
1. 数据与方法（80-120 字）：ERA5 + OLS + 95% Student-t CI
2. 主要发现（200-300 字）：按 slope 降序列前 3 城，带数字 + CI + 趋势方向
3. 区域对比（150-200 字）：照搬资料员表分类，**不许**自创"沿海/内陆/南方"
4. 局限与展望（100-150 字）：自相关、单像元、城市选择有限

规则：
- 每个数字来自 csv 或图，不许编造
- **禁用词**：显著 / 大幅 / 明显 / 确凿 / 毫无疑问 / 毋庸置疑
  → 替换：CI 不含 0 / 幅度较大 / 方向一致
- 不许引入 ENSO / 季风 / 城市热岛等无 csv 支撑的物理解释
- 平实中文，每句 ≤ 40 字
- 引用图："（见图 1 / outputs/年均气温_折线.png）"

保存到 outputs/起草员_v1.md
```

## 3. 审稿员（Sonnet 4.6 / DeepSeek-R1；合并审稿 + 批判 + 润色）

```
你是【审稿员】。.claude/agents/严格审稿员.md 是你的人格模板。

读 outputs/起草员_v1.md + outputs/资料员_主题表.md。
对**每个数字**调 verify_number()，found=false 列进「编造数字」节。

输出一份 outputs/草稿_v2.md，分两部分：

## 上半：审稿报告
按 4 类逐项过：
1. 编造数字：[行号 / 原文 / 反证 / 建议]
2. 禁用词：原文 + 替换建议
3. 超出样本的解释：30 年单像元 OLS 不能支撑 ENSO / 城市热岛因果归因
4. 自造分类：标签是否来自资料员表

打分表（每数字回链 / 无禁用词 / 分类来自表 / 字数 600-1000 / 4 章节齐全）+ 总评。

## 下半：重写后的 v2 正文
按审稿意见改 v1，每句 ≤ 40 字。末尾「修改记录」。

**注意**：审稿和重写一次出，不要拆两轮——课堂时间紧。
```

## 4. 研究者（你）

- 补「AI 使用声明」
- 改成 `outputs/最终稿.md`，再核验一次

## 什么时候切五角色 / K-Dense Skills

| capstone 三角色（本文） | 五角色 + K-Dense |
| --- | --- |
| 600-1000 字中文小综述 | 4000+ 字 IMRAD 长论文 |
| 数据全在 csv | 需要先做文献检索 + 引用管理 |
| 单数据集 + 单方法 | 多数据源 + 方法对比 |
| 课堂演示（1-2 课时） | 真投期刊（数周） |

真投论文 → 第 06 章的 K-Dense Skills + 第 09 章五角色。
